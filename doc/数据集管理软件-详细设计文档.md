# 第2章 总体架构设计

## 2.1 架构概述

系统采用"上层Web应用 + 底层IGinX支撑"的B/S架构模式，底层完全复用IGinX 0.8.0的存储与计算能力，不新增独立数据库，不改动IGinX内核。所有元数据（数据集元信息、作业配置、用户信息、操作日志等）均通过IGinX Session接口以`relational_system.*`前缀写入IGinX存储。

### 2.3.1 模块职责说明

- **datasetman-common**：提供跨模块共享的基础设施，包括CORS跨域配置（`WebConfig`）、统一响应模型（`Result<T>`）、全局异常处理、通用工具类（`CommonUtil`用于SQL校验、`ConvertUtil`用于IGinX数据转换）。
- **datasetman-auth**：负责用户认证、授权、操作日志记录。包含JWT Token签发与校验、Spring Security配置、基于注解的细粒度权限控制（`@RequirePermission`）、操作日志AOP切面（`@OperationLog`）、用户与角色的DAO层管理。
- **datasetman-core**：系统核心业务逻辑，包含数据源管理、数据查询、数据集管理、Transform作业编排与执行、函数管理（Transform/UDF）等全部业务Service与Controller。
- **datasetman-server**：Spring Boot启动入口，承载静态前端资源，提供`application.yml`配置文件。

#### 数据集存储设计

数据集元数据存储在IGinX中，使用两个前缀：

- **`dataset.*`**：存储数据集SQL定义（以二进制格式存储）
- **`relational_system.dataset_meta`**：存储数据集元信息（名称、版本、操作人、IP等）

`DatasetEntity`使用IGinX Session v2的`@Measurement`和`@Field`注解，通过`WriteClient.writeMeasurement()`直接写入。

#### SQL安全校验

`CommonUtil.validateSql()`方法对SQL进行安全校验：
- 仅允许 `SELECT` 类型SQL语句
- 禁止危险关键字：`DELETE`、`UPDATE`、`INSERT`、`DROP`、`ALTER`、`TRUNCATE`

#### 版本管理设计

数据集采用版本树结构管理变更历史：
- 每次保存生成唯一版本号（基于时间戳）
- `parent`字段记录父版本的时间戳，根版本`parent=0`
- `getVersionHistory()`查询所有版本并构建树形结构返回前端
- 删除采用逻辑删除（`deleted=true`），保留历史记录

# 第4章 认证与安全设计

## 4.1 认证架构

系统采用Spring Security + JWT的无状态认证方案，不使用Session。

```mermaid
graph TB
    subgraph 认证流程
        L1[用户登录] --> L2[AuthController.login]
        L2 --> L3[AuthenticationManager.authenticate]
        L3 --> L4[CustomUserDetailsService.loadUserByUsername]
        L4 --> L5[校验BCrypt密码]
        L5 --> L6[签发JWT Token + RefreshToken]
        L6 --> L7[返回Token给前端]
    end

    subgraph 请求鉴权流程
        R1[前端携带Bearer Token] --> R2[JwtAuthenticationFilter]
        R2 --> R3[解析并校验Token]
        R3 --> R4[设置SecurityContext]
        R4 --> R5[RequirePermission拦截器]
        R5 --> R6{权限校验}
        R6 -->|通过| R7[执行业务逻辑]
        R6 -->|拒绝| R8[返回403]
    end
```

## 4.2 安全配置

### 4.2.1 SecurityConfig 配置

- **CSRF**：禁用（前后端分离，使用JWT）
- **Session**：`STATELESS`（无状态）
- **CORS**：允许所有源、所有方法、所有头
- **放行路径**：静态资源、登录页、`/api/auth/**`、API文档
- **认证路径**：所有 `/api/**` 请求需要JWT认证
- **异常处理**：API请求返回401 JSON，页面请求重定向到登录页

### 4.2.2 权限控制

采用基于注解的细粒度权限控制：

```mermaid
graph LR
    A[@RequirePermission 注解] --> B[RequirePermission拦截器]
    B --> C{用户是否拥有该权限?}
    C -->|是| D[放行执行]
    C -->|否| E[抛出AccessDeniedException]
    
    F[@OperationLog 注解] --> G[OperationLogAspect AOP切面]
    G --> H[记录操作人/IP/参数/结果/耗时]
```

#### 权限枚举

| 权限分组 | 权限项 |
|---|---|
| 数据源管理 | DATASOURCE_CREATE / READ / UPDATE / DELETE |
| 数据管理 | DATA_CREATE / READ / UPDATE / DELETE |
| 通用 | CREATE / READ / UPDATE / DELETE |
| 用户管理 | USER_CREATE / READ / UPDATE / DELETE |

### 4.2.3 JWT配置

| 配置项 | 值 | 说明 |
|---|---|---|
| secret | 自定义密钥 | JWT签名密钥 |
| expiration | 28800000ms (8小时) | Access Token有效期 |
| refresh-expiration | 43200000ms (12小时) | Refresh Token有效期 |

### 4.2.4 操作日志

通过`@OperationLog`注解 + AOP切面自动记录操作日志，包含：
- 操作人、IP地址
- 操作描述、操作类型（CREATE/UPDATE/DELETE/QUERY/IMPORT/EXPORT/LOGIN）
- 请求方法、请求参数、返回结果
- 执行状态、耗时、错误信息
- 请求URI、User-Agent

# 第9章 关键流程端到端设计

## 9.1 数据集创建到Transform执行全链路

```mermaid
sequenceDiagram
    participant U as 数据工程师
    participant F as 前端
    participant DS_API as DatasetController
    participant DS_SVC as DatasetService
    participant TC_API as TransformCompareController
    participant TC_SVC as TransformCompareService
    participant TJ_API as TransformJobController
    participant TJ_SVC as TransformJobService
    participant IGinX

    Note over U,IGinX: 步骤1: 注册数据源(如已注册则跳过)

    Note over U,IGinX: 步骤2: 创建数据集
    U->>F: 编写SQL，点击测试
    F->>DS_API: POST /api/dataset/testsql
    DS_API->>DS_SVC: testSQL(sql)
    DS_SVC->>IGinX: executeQuery(sql)
    IGinX-->>DS_SVC: 结果
    DS_SVC-->>F: 测试结果
    U->>F: 确认保存
    F->>DS_API: POST /api/dataset/save
    DS_API->>DS_SVC: saveDataset(request)
    DS_SVC->>IGinX: writePoint(SQL定义)
    DS_SVC->>IGinX: writeMeasurement(元信息)
    DS_SVC-->>F: DatasetEntity

    Note over U,IGinX: 步骤3: 编排Transform作业
    U->>F: 选择数据集+Transform函数，配置调度
    F->>TC_API: POST /api/transform-compare/save
    TC_API->>TC_SVC: saveTransform(request)
    TC_SVC->>IGinX: writeMeasurement(编排配置)
    TC_SVC-->>F: TransformCompareEntity

    Note over U,IGinX: 步骤4: 提交执行
    U->>F: 点击"运行"
    F->>TJ_API: PUT /api/transform-job/commit/{createTime}
    TJ_API->>TJ_SVC: commitJob(createTime)
    TJ_SVC->>TC_SVC: queryJob(createTime)
    TC_SVC-->>TJ_SVC: TransformCompareEntity
    TJ_SVC->>DS_SVC: queryMeta(dataset)
    DS_SVC-->>TJ_SVC: DatasetEntity (含SQL)
    TJ_SVC->>IGinX: commitTransformJob(taskInfoList, ...)
    IGinX-->>TJ_SVC: jobId
    TJ_SVC->>IGinX: writeMeasurement(执行实例)
    TJ_SVC-->>F: TransformJobEntity

    Note over U,IGinX: 步骤5: 查询状态
    U->>F: 点击"刷新"
    F->>TJ_API: GET /api/transform-job/status/{jobId}
    TJ_API->>TJ_SVC: statusJob(jobId)
    TJ_SVC->>IGinX: queryTransformJobStatus(jobId)
    IGinX-->>TJ_SVC: JobState
    TJ_SVC->>IGinX: writeMeasurement(更新状态)
    TJ_SVC-->>F: 最新状态

    Note over U,IGinX: 步骤6: 查看血缘
    U->>F: 点击"历史图谱"
    F->>TJ_API: GET /api/transform-job/bloodline?datasetPath=...
    TJ_API->>TJ_SVC: queryAllJobs(datasetPath, 1, true)
    TJ_SVC->>IGinX: SELECT * FROM transform_job WHERE ...
    IGinX-->>TJ_SVC: 完成的作业列表
    TJ_SVC-->>F: DAG数据
    F->>F: ECharts渲染血缘图
```
